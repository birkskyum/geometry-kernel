# Compatibility Contract

The kernel exists to prevent geometry-engine drift. A pure-Rust backend must
not be considered a replacement for GEOS/JTS-style behavior until it passes the
contract below.

## Operation-Level Contract

Each operation fixture records:

- operation name
- input geometries in planar meter coordinates
- operation parameters
- reference output generated by the GEOS reference backend
- tolerance policy

The first operation targets are:

| Operation | Exactness policy |
| --- | --- |
| `polygon_area` | Absolute tolerance |
| `largest_polygon` | Exact component choice after canonicalization |
| `buffer_polygon` | Area tolerance plus topology/count checks |
| `line_buffer` | Area tolerance plus topology/count checks |
| `intersection` | Area tolerance plus canonical topology checks |
| `difference` | Area tolerance plus canonical topology checks |
| `line_polygon_intersections` | Point count exact, coordinate tolerance |

## Model-Level Contract

When this kernel is used by a model, operation-level similarity is not enough.
The model-level output must preserve:

- row count exactly
- tree marker count exactly
- strip count exactly
- species counts exactly
- ground-cover area totals within explicit tolerance
- strip area totals within explicit tolerance

## Backend Promotion Rule

The default backend can change only when the candidate backend passes every
fixture in both suites. A smaller bundle or faster runtime is not enough if it
changes model output.
